# 취업좀하자 기능명세서

문서 상태: 기능 정의·단계별 구현 중 · 작성일: 2026년 10월 5일

이 문서는 개발 계획서 이후 합의한 기능과 동작 규칙을 정리한다. 수용 조건은 앞으로 구현 결과를 확인할 기준이며, 현재 검증 완료를 의미하지 않는다.

현재 백엔드는 GitHub 인증·프로필 API와 비공개 초안 생성·목록·불러오기·버전 조건 저장까지 구현했다. 초안은 유형별 선택 안내 항목과 Markdown 본문을 저장하며 본인만 접근한다. 초안 저장 기반 구현을 10초 자동 저장 UI·공개 발행 완료로 보지 않는다. 정식 편집기·자동 저장·공개 발행·삭제·검색은 후속 단계에서 진행한다.

## 1. 이용자와 접근 범위

| 이용자 | 가능한 작업 |
|---|---|
| 방문자 | 공개 포트폴리오·공개 기록 조회, 전체·개인 공개 기록 검색 |
| GitHub 인증 후 프로필 미등록 사용자 | 서비스 프로필 등록, 공개 기록 탐색 |
| 프로필 등록 회원 | 본인의 기록 작성·수정·삭제, 공개 범위 변경, 핀·보관·기록 연결, 개인 아카이브 관리 |

타인의 임시저장·비공개 기록, 수정 중인 초안, 보관함은 접근할 수 없다. 타인의 기록을 수정·삭제하거나 핀으로 고정할 수 없다.

## 2. 화면 구성

| 화면 | 주요 기능 |
|---|---|
| 전체 탐색 | 공개 기록 목록, 검색어·글 유형·기술 태그 필터, 기록 상세 이동 |
| 로그인 | GitHub 계정 인증, 취소·실패 안내 |
| 최초 프로필 설정 | 닉네임·개인 주소 등록, 선택 프로필 입력 |
| 개인 공개 포트폴리오 `/u/{아이디}` | 공개 프로필, 대표 프로젝트 최대 3개, 공개 기록과 개인 검색 |
| 내 아카이브 | 본인의 공개·비공개·임시저장 기록 검색·조회·관리 |
| 글 작성·수정 | 유형별 안내 항목, 자유 본문 편집기, 이미지, 태그, 연결 기록, 저장·공개 범위 |
| 기록 상세 | 본문·사진·코드·수식, 작성자, 관련 기록, 보관 버튼; 본인 글에는 수정·삭제 |
| 내 보관함 | 보관한 공개 기록 목록, 상세 이동, 보관 해제 |
| 프로필 관리 | 프로필 수정, 대표 프로젝트 선택·해제·순서 변경 |

## 3. 기능 정의

### F01. GitHub 로그인과 회원 프로필

- GitHub 계정으로 로그인한다. 같은 GitHub 계정은 기존 서비스 계정으로 접속한다.
- 첫 로그인 후 서비스 프로필을 등록한다. GitHub 로그인과 서비스 프로필 등록은 별도 단계다.
- **필수 항목:** 닉네임, 개인 주소 아이디.
- **선택 항목:** 전공·관심 분야, 짧은 소개.
- 개인 주소 아이디는 다른 회원과 중복될 수 없다. 중복이면 입력을 유지하고 변경을 안내한다.
- 기존 회원은 최초 설정을 반복하지 않고 서비스를 이용한다. 로그아웃 후에는 본인 전용 데이터에 접근할 수 없다.
- GitHub 로그인을 했다고 비공개 저장소 접근 권한까지 요구하지 않는다.

**수용 조건:** 로그인 성공·취소·실패를 구분하고, 프로필 등록 후 `/u/{아이디}`에서 공개 프로필을 확인할 수 있다. 다른 사용자의 주소로 등록하려는 요청은 거부한다.

### F02. 글 유형과 작성 항목

새 글 작성 시 **프로젝트 / 공부 기록 / 기타** 중 하나를 선택한다.

| 유형 | 선택 안내 항목 |
|---|---|
| 프로젝트 | 소개, 목표, 팀 구성·내 역할, 사용 기술·도구·장비, 문제와 해결, 구현·실험 결과 |
| 공부 기록 | 학습 주제, 참고 자료, 이해한 내용, 실습, 남은 질문 |
| 기타 | 별도 안내 항목 없이 자유 본문 |

- 공개 또는 비공개 정식 저장 시 **제목·글 유형·본문만 필수**다.
- 안내 항목, 태그, 사진, 외부 링크, 연결 기록은 선택 입력이다.
- 안내 항목을 비워도 저장할 수 있다. 안내 문구 자체가 기록 본문으로 저장되지 않는다.
- 본문이 빈 서식·공백만 포함하면 정식 저장 시 입력을 안내한다. 사진·코드·수식 등 실제 본문 콘텐츠도 본문으로 인정한다.
- 임시저장은 미완성 글을 보관할 수 있도록 필수 조건을 완화한다.

**수용 조건:** 세 필수 항목만 입력한 글을 저장할 수 있고, 선택 항목 없이 작성한 글도 정상 표시된다. 제목이 없는 임시저장 글은 목록에서 ‘제목 없는 기록’으로 구분한다.

### F03. 블로그형 본문 편집기

- 버튼으로 제목, 목록, 링크, 사진, 코드 블록, 수식을 삽입한다.
- 작성 화면에서 서식과 콘텐츠를 확인한다.
- 코드 블록은 들여쓰기·줄바꿈을 보존한다.
- 수식은 분수·적분 등을 수학식으로 표시한다.
- 저장 후 다시 수정할 때 본문과 선택 안내 항목이 유지된다.
- 임의 스크립트와 위험한 링크를 실행하지 않도록 입력 검증·안전한 표시를 적용한다.

**수용 조건:** 본문 작성→저장→재조회→재편집 과정에서 텍스트, 목록, 사진, 코드 들여쓰기, 수식이 유지된다.

### F04. 임시저장과 저장 상태

- 내용이 변경된 후 **10초 동안 추가 입력이 없으면 자동 임시저장**한다.
- 계속 입력하면 시간을 다시 센다. 변경 사항이 없으면 같은 내용을 반복 저장하지 않는다.
- 자동 임시저장과 별도로 수동 임시저장 버튼을 제공한다.
- 작성 상태를 **저장 중 / 저장 완료 / 저장 실패**로 표시한다.
- 저장 완료는 서버 저장 성공을 확인한 뒤 표시한다.
- 저장 실패 시 편집 화면의 입력을 유지하고 수동 재시도를 제공한다.
- 서버에 저장된 초안은 새로고침·재로그인 후 다시 열 수 있다. 실패로 서버에 저장되지 않은 입력까지 복구된다고 표시하지 않는다.
- 초안은 본인만 접근한다. 임시저장으로 공개 기록이 자동 생성되지 않는다.

**수용 조건:** 입력이 멈춘 뒤 자동저장되고, 새로고침 후 저장된 초안이 복구된다. 네트워크 실패 중에는 ‘저장 완료’가 표시되지 않는다. 연속 저장 요청의 오래된 응답이 최신 내용을 덮어쓰지 않는다.

### F05. 정식 저장·공개 범위·공개 글 수정

신규 글의 흐름:

`작성 → 임시저장(본인만 보기) → 공개하기 또는 비공개로 저장하기`

| 상태 | 본인 | 방문자·다른 회원 |
|---|---|---|
| 임시저장 | 조회·편집 가능 | 조회 불가 |
| 비공개 저장 | 조회·편집 가능 | 조회 불가 |
| 공개 저장 | 조회·편집 가능 | 공개된 내용 조회 가능 |
| 공개 글을 수정 중인 초안 | 수정 내용 조회·편집 가능 | 마지막으로 공개 적용한 내용만 조회 가능 |

- 공개 또는 비공개 정식 저장 전에 F02 필수 항목을 검사한다.
- 공개 글을 수정할 때 자동 임시저장은 **본인용 작업 사본**에 저장한다.
- **‘수정 내용 적용’**을 눌러 성공한 후 공개 화면에 수정 내용을 반영한다.
- 공개 범위 변경도 명시적인 저장·적용 동작으로 처리한다. 자동저장만으로 공개 범위가 바뀌지 않는다.
- 공개 글을 비공개로 적용하면 공개 탐색·포트폴리오·핀·타인의 보관함·관련 기록에서 내용을 제외한다.
- 이미 방문자가 내려받거나 캡처한 내용까지 회수하는 기능은 제공하지 않는다.

**수용 조건:** 공개 글을 수정·자동저장하는 동안 다른 계정에서는 기존 공개 내용이 유지된다. 수정 적용 후 새 내용이 표시되고, 비공개 전환 후 직접 URL로 요청해도 타인은 접근할 수 없다.

### F06. 내 아카이브와 글 관리

- 본인의 공개·비공개·임시저장 기록을 조회하고 상태를 구분한다.
- 기록을 열어 수정하거나 삭제할 수 있다.
- 삭제 전 확인을 제공한다. 삭제 요청 실패 시 목록에서 임의로 제거하지 않는다.
- 삭제된 기록은 공개 목록·포트폴리오·핀·보관함·관련 기록에서 제거한다.
- 수정 중인 작업 사본만으로 삭제가 수행되지 않는다.

**수용 조건:** 타인의 기록 ID로 수정·삭제를 요청해도 거부한다. 삭제 성공 후 관련 화면에 삭제된 기록이 남지 않는다.

### F07. 개인 포트폴리오와 대표 프로젝트 핀

- 개인 공개 페이지에 닉네임, 입력한 전공·관심 분야·소개, 공개 기록을 표시한다.
- 본인의 **공개 프로젝트만 최대 3개**까지 상단에 고정한다.
- 핀 해제와 표시 순서 변경을 제공한다. 순서는 DB에 저장한다.
- 공부 기록·기타·임시저장·비공개 글과 타인의 프로젝트는 고정할 수 없다.
- 네 번째 프로젝트를 고정하려 하면 기존 핀을 해제하도록 안내한다.
- 핀 프로젝트가 삭제되거나 비공개가 되면 상단에서 제외한다. 다시 공개해도 사용자가 직접 고정한다.

**수용 조건:** 최대 3개 제한이 서버에서도 적용되고, 새로고침 후 핀과 순서가 유지된다. 공개 포트폴리오에는 임시저장·비공개 정보가 표시되지 않는다.

### F08. 보관함

- **다른 사람의 공개 기록**을 저장·해제한다. 프로젝트·공부 기록·기타를 보관할 수 있다.
- 보관함은 로그인한 회원 본인만 조회한다.
- 같은 글을 여러 번 보관해도 한 번만 저장된다.
- 새로고침·재로그인 후에도 보관한 기록이 유지된다.
- 원글이 삭제되거나 비공개로 바뀌면 보관함에서 그 내용을 보여주지 않는다.
- 보관함은 원글의 복사본을 생성하는 기능이 아니다.

**수용 조건:** 보관→새로고침→재조회→해제 과정이 유지되고, 다른 계정의 보관함을 조회할 수 없다. 보관한 원글이 비공개가 되면 상세 URL에서도 타인의 접근을 거부한다.

### F09. 전체·개인 검색과 태그 필터

- 검색 대상은 **제목·본문·태그**, 기본 정렬은 **최신순**이다.
- 전체 탐색에서는 모든 공개 기록을 검색한다.
- 개인 포트폴리오에서는 해당 회원의 공개 기록만 검색한다.
- 본인의 관리 화면에서는 자신의 비공개·임시저장 기록도 검색한다.
- 글 유형(전체 / 프로젝트 / 공부 기록 / 기타)과 기술 태그로 범위를 좁힌다.
- 여러 태그를 선택하면 **선택한 태그를 모두 포함하는 기록**을 보여준다.
- 검색어와 유형·태그 조건은 함께 적용한다. 빈 검색어는 현재 필터에 해당하는 목록을 보여준다.
- 결과 목록을 나누어 조회하며, 페이지 크기와 입력 길이 제한은 API 명세서에서 구체화한다.
- 요청 중 로딩, 결과 없음, 요청 실패와 재시도를 구분한다.
- 검색 조건을 빠르게 바꿔도 오래된 응답이 최신 결과를 덮어쓰지 않는다.

**수용 조건:** `React`와 `보안` 태그를 함께 선택하면 두 태그가 모두 있는 글만 출력된다. 타인의 비공개 글은 제목·본문·태그·결과 개수에서도 노출되지 않는다.

### F10. 프로젝트–공부 기록 연결

- **본인이 작성한 프로젝트와 공부 기록만** 서로 연결한다.
- 프로젝트 하나에 여러 공부 기록을, 공부 기록 하나에 여러 프로젝트를 연결할 수 있다.
- 한 쌍은 중복 연결되지 않는다. 연결 해제를 제공한다.
- 프로젝트와 공부 기록 상세 양쪽에서 연결된 기록을 확인한다.
- 본인의 관리 화면에서는 본인의 비공개·임시저장 기록도 연결 대상으로 선택할 수 있다.
- 방문자에게는 공개된 관련 기록만 표시한다. 비공개 기록의 제목·본문·사진 등도 노출하지 않는다.
- 글 삭제 또는 비공개 전환 시 공개 관련 기록 목록에서도 제외한다.

**수용 조건:** 양쪽 화면에 연결이 반영되고, 타인의 글이나 프로젝트–프로젝트·공부–공부 조합 연결 요청은 거부한다.

### F11. GitHub 공개 저장소 가져오기

- 공개 GitHub 저장소 URL을 입력하고 가져오기를 실행한다.
- 저장소 이름, 설명, 사용 언어, README를 가져와 **프로젝트 초안**을 만든다.
- 가져온 뒤 제목·본문·역할·기술 등은 자유롭게 수정한다. 원문 저장소 URL도 보관한다.
- 저장소 설명과 README가 없으면 비워두고 직접 입력할 수 있다.
- 가져온 글은 자동 공개하지 않는다. 정식 저장 시 일반 글과 같은 필수 항목 규칙을 적용한다.
- 기존 작성 내용이 있다면 별도의 초안을 생성하여 자동으로 덮어쓰지 않는다.
- 원본 변경에 따른 자동 동기화는 하지 않는다. 비공개 저장소는 이번 범위에서 가져오지 않는다.
- 잘못된 URL, 존재하지 않거나 접근 불가능한 저장소, 요청 제한·네트워크 실패를 구분하여 안내한다.
- GitHub 로그인과 저장소 가져오기를 분리하고 비공개 저장소 접근 권한을 요구하지 않는다.

**수용 조건:** 공개 저장소를 가져온 후 사용자가 수정할 수 있고, 원본 README 변경이 서비스의 글을 자동 변경하지 않는다. 가져오기 실패가 기존 입력을 지우지 않는다.

### F12. 사진 업로드

- **JPG·PNG·WebP**를 지원한다.
- 한 장 최대 **5MB**, 글당 최대 **10장**이다.
- 업로드 중·완료·실패를 표시하고 크기·유형·개수 초과를 안내한다.
- 서버에서도 실제 파일 유형·크기·소유권을 확인한다. 확장자만 바꾼 파일을 신뢰하지 않는다.
- 저장된 사진을 본문에 삽입하고 삭제·교체할 수 있다.
- 임시저장·비공개 글의 사진과 공개 글 수정 초안에만 있는 사진은 본인만 접근한다.
- 공개 글에 적용된 사진만 방문자에게 제공한다. 공개 글 수정 중 사진을 제거해도 적용 전까지 기존 공개 화면은 유지한다.
- 글이 비공개가 되면 타인의 새로운 이미지 접근을 차단한다. 이미 다운로드한 파일은 회수하지 않는다.
- 삭제·교체된 불필요한 파일의 정리는 현재 공개본·초안의 참조를 확인한 뒤 처리한다.

**수용 조건:** 10장을 초과하거나 한 장이 5MB를 초과하면 거부하고, 다른 계정으로 비공개 사진 URL을 요청해도 접근할 수 없다. 실패한 업로드를 완료된 첨부로 저장하지 않는다.

### F13. 반응형 화면과 공통 상태

- 모바일·PC에서 탐색·검색·상세·작성·관리를 지원한다.
- 입력 라벨, 키보드 조작, 저장·오류 안내를 제공한다.
- 로딩 중 동일한 저장 작업의 중복 실행을 제한한다.
- 저장·삭제·핀·보관 등은 서버 성공을 확인한 뒤 완료로 표시한다.
- 세션 만료는 다시 로그인을 안내하고, 편집 중인 입력을 즉시 지우지 않는다.
- 공개 상세 URL로 비공개·삭제된 글을 요청하면 내용을 표시하지 않는 접근 불가 화면을 제공한다.

**수용 조건:** 모바일에서 필수 작업을 수행할 수 있고, 네트워크 실패·세션 만료가 성공으로 표시되지 않는다.

## 4. 공개 데이터 노출 규칙

| 데이터 | 공개 탐색·포트폴리오 | 본인 관리 화면 | 타인 직접 요청 |
|---|---|---|---|
| 공개 프로필 | 표시 | 표시·수정 | 공개 정보만 허용 |
| 공개 적용된 글·사진 | 표시 | 표시·수정 | 허용 |
| 비공개 글·사진 | 제외 | 표시·수정 | 거부 |
| 임시저장 글·사진 | 제외 | 표시·수정 | 거부 |
| 공개 글의 수정 초안 | 제외; 기존 공개본 유지 | 표시·수정 | 거부 |
| 보관함 | 제외 | 본인만 표시 | 거부 |
| 공개된 관련 기록 | 표시 | 표시·관리 | 허용 |
| 비공개 관련 기록 | 제목·개수 등에서도 제외 | 본인만 표시 | 거부 |

이 규칙은 화면 표시뿐 아니라 API·DB·파일 저장소 접근에도 적용한다.

## 5. 후속 확장 범위

- 댓글·팔로우·좋아요
- 비공개 GitHub 저장소 가져오기와 자동 동기화
- Notion 내용 가져오기·내보내기
- Tistory 붙여넣기용 글 내보내기

GitHub·Notion·Tistory 원문 링크는 선택 입력으로 기록에 연결할 수 있다. 서비스의 Tistory 연동 기능과 개발 과정의 블로그 게시 작업은 구분한다.

## 6. 명세에서 구체화한 보완 규칙

아래는 합의한 기능이 충돌하지 않도록 이 문서에서 구체화한 동작이다. 구현 전에 함께 확인한다.

- 공개 글 수정 내용은 작업 사본으로 저장하고 명시적으로 적용한다.
- 공개 범위 변경은 자동저장으로 수행하지 않는다.
- 가져오기는 별도 초안을 만들어 기존 입력을 보호한다.
- 공개 핀을 비공개로 전환했다가 다시 공개해도 자동으로 고정하지 않는다.
- 서버에 저장하지 못한 입력까지 새로고침 후 복구된다고 보장하지 않는다.

개인 주소 문자 규칙, 입력 길이·태그 개수, 목록 페이지 크기, 파일 제한의 정확한 바이트 기준, 초안 충돌 처리 등 세부 제약은 API·데이터 설계에서 확정한다.
