공대생이 프로젝트와 공부 기록을 모아 자신의 포트폴리오를 만들 수 있는 서비스, 취업좀하자를 개발하려고 한다. 먼저 서비스의 기능과 기술 구성, 개발 순서를 계획서로 정리했다. 이후 구현 과정과 결과도 이 글에 이어서 작성할 예정이다.

공대생 포트폴리오 서비스 ‘취업좀하자’ 개발 계획서

1. 서비스 개요

취업좀하자는 개발·통신·보안 등 공학 분야의 학생들이 프로젝트와 공부 기록을 작성하고, 이를 자신의 포트폴리오로 구성하는 웹 서비스다.

여러 사용자가 가입하여 각자의 프로필과 아카이브를 관리한다. 공개한 기록은 개인 포트폴리오와 전체 탐색 화면에서 보여주고, 비공개 기록은 본인만 확인할 수 있도록 한다.

2. 대상 사용자와 서비스 특색

주요 대상은 프로젝트·실습·학습 경험을 정리하고 싶은 공대생이다. 코드, 기술 설명, 사진, 수식과 실험 결과를 활용하여 자신의 경험을 표현할 수 있도록 구성한다.

  • 유형별 작성 양식: 프로젝트 / 공부 기록 / 기타를 선택하면 유형에 맞는 안내 항목을 제공한다. 자세한 내용은 자유 본문에 작성한다.
  • 프로젝트와 학습의 연결: 프로젝트에 관련 공부 기록을 연결하고, 공부 기록에서 활용한 프로젝트를 확인한다.
  • 개인 아카이브와 공개 포트폴리오: 공개·비공개 기록을 관리하고, 대표 프로젝트를 상단에 고정한다.

3. 계획 기능

기능 동작
회원별 포트폴리오 회원마다 프로필과 개인 포트폴리오 페이지를 제공한다.
글 유형 선택 새 글을 작성할 때 프로젝트 / 공부 기록 / 기타 중 하나를 선택한다.
프로젝트 작성 목표, 내 역할, 사용 기술·장비, 문제와 해결, 결과를 안내하고 자유 본문을 제공한다.
공부 기록 작성 학습 주제, 참고 자료, 이해한 내용, 실습, 남은 질문을 안내하고 자유 본문을 제공한다.
기타 작성 제목·태그와 자유 본문으로 회고·활동 후기 등을 작성한다.
블로그형 편집기 버튼으로 제목·목록·링크·사진·코드 블록·수식을 삽입하고 본문을 편집한다.
글 관리 본인이 작성한 기록을 조회·수정·삭제한다.
공개 범위 전체 공개 / 나만 보기를 선택하고 작성 후 변경할 수 있다. 비공개 기록은 본인만 접근한다.
대표 프로젝트 핀 자신의 공개 프로젝트를 포트폴리오 상단에 고정·해제한다. 비공개 전환 시 공개 화면에서 제외한다.
보관함 다른 사람의 공개 기록을 저장·해제한다. 새로고침과 재로그인 후 유지한다. 원글이 비공개가 되면 내용을 노출하지 않는다.
전체 검색 전체 공개 기록을 검색하고 글 유형·기술 태그로 범위를 좁힌다.
개인 검색 개인 포트폴리오의 공개 기록을 검색한다. 본인의 관리 화면에서는 비공개 기록도 검색한다.
기록 연결 자신의 프로젝트와 공부 기록을 연결하고 양쪽에서 관련 기록을 확인한다. 방문자에게 비공개 기록은 보여주지 않는다.
상태 처리 로딩, 검색 결과 없음, 요청 실패를 구분하여 표시한다. 저장 실패 시 입력을 유지한다.
반응형 화면 모바일과 PC에서 탐색·검색·작성·관리 화면을 사용할 수 있도록 구성한다.

댓글·팔로우·좋아요는 후속 확장 기능으로 둔다.

5. 외부 서비스 연동

서비스 연동 계획
GitHub 저장소 링크 연결을 제공하고, 공개 저장소의 설명·README 등을 프로젝트 작성에 활용하는 가져오기 기능을 검토한다.
Notion 원문 링크 연결을 제공하고, 사용자가 접근을 허용한 페이지의 내용 가져오기·내보내기를 확장 기능으로 검토한다.
Tistory 원문 링크 연결과 붙여넣기용 글 내보내기를 검토한다. 공식 Open API가 종료되어 API를 통한 자동 발행은 지원 범위에서 제외한다.

기존 기록의 자동 동기화와 비공개 저장소 접근은 후속 확장 범위로 둔다.

7. 권한과 데이터 보호

  • 기록 조회·수정·삭제 시 작성자와 공개 범위를 확인한다.
  • Supabase RLS 정책으로 사용자별 데이터 접근을 제한한다.
  • 비공개 글과 첨부 사진은 본인만 접근할 수 있도록 구성한다.
  • 편집기 입력을 검증하고 본문을 안전하게 표시하여 스크립트 실행을 방지한다.
  • 업로드 파일의 유형·크기·소유권을 확인한다.
  • 비밀 API 키, 서비스 관리자 키, 사용자 연동 토큰은 GitHub에 올리지 않는다.
  • 환경 변수는 .env로 분리하고 .gitignore를 적용한다. .env.example에는 실제 비밀값 대신 설정 항목과 설명을 작성한다.

8. 개발 순서와 일정

개발 목표 일정: 2026년 10월 5일 내 구현·검증·배포 완료.

  1. 계획 정리: 서비스 범위와 계획 기능을 정리한다.
  2. 기능명세서 작성: 화면별 기능과 동작 조건을 구체화한다.
  3. 화면 설계: 공개 포트폴리오, 전체 탐색, 개인 관리, 글 작성 화면을 설계한다.
  4. API 명세서·ERD 작성: 요청·응답·권한·오류와 데이터 관계를 설계한다.
  5. 개발 환경 구성: VS Code에서 프로젝트와 Git, 환경 변수, DB·인증 설정을 구성한다.
  6. 핵심 기능 구현: 로그인·프로필 → 글 작성·공개 범위 → 조회·검색 → 핀·보관 → 기록 연결 순으로 구현한다.
  7. 검증과 배포: 사용자별 권한, 데이터 유지, 반응형 화면, 실패 상태를 확인하고 Vercel에 배포한다.
