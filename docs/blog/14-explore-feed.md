# 탐색 피드와 기록 상세 구현

프로젝트·공부 기록·기타를 찾아볼 수 있는 첫 서비스 화면을 구현했다. Vercel 공식 사이트를 실제 브라우저로 확인하고 흰 배경, 흑백 타이포그래피, 넓은 여백과 간결한 헤더를 참고했다. 카드와 검색 UI에는 얇은 zinc 테두리를 적용했다. Vercel의 서비스 콘텐츠나 로고를 사용하지 않고 취업좀하자의 탐색 흐름으로 구성했다. 사이트 전체를 픽셀 단위로 복제한 것은 아니다.

## API 요청부터 화면까지

브라우저가 기존 Supabase 세션을 확인한다. 실제 모드에서는 `GET /api/records?feed=1`에 검색어·유형·태그·offset을 전달한다. 서버는 기존 공개 검색 함수로 최대 20개를 가져오고 `feed_metadata`를 한 번 호출해 작성자, 핀, 공개 공부 기록 연결 수와 현재 회원의 보관 여부를 붙인다. 카드마다 작성자·보관·연결 조회를 반복하지 않는다.

기존 필드 이름은 유지한다. 브라우저에서는 owner_id → ownerId, excerpt → summary처럼 검증 후 화면 타입으로 변환한다. 백엔드의 소문자 유형을 그대로 사용하고 화면에서 한국어로 표시한다. 날짜는 서울 기준이다. 초안·비공개 기록은 공개 탐색에 섞지 않는다.

보관 클릭은 먼저 아이콘을 채우고 PUT/DELETE 요청을 보낸다. 성공하면 서버 saved 값으로 확정하고 실패하면 이전 상태로 되돌린다. 요청 중 같은 버튼을 잠그고 본인 글은 비활성화한다. 로그아웃·계정 변경 시 이전 요청 결과를 새 회원 화면에 적용하지 않는다.

데모는 `?demo=1`로 명시적으로 선택한다. 실제 DB를 변경하지 않는 24개 샘플에 검색과 페이지 규칙을 적용하고, 보관은 데모 전용 localStorage에 저장한다. 실제 서버 실패 시 데모로 자동 전환하지 않는다. 손상된 저장 데이터나 저장소 차단은 안내하고 저장 실패를 롤백한다.

본문은 텍스트로 렌더링해 임의 HTML 실행을 막는다. 사진은 `/api/images/{UUID}` 경로만 표시한다. 전체 Markdown 편집·표시 기능은 작성기 단계에서 확장한다.

## 실제 검증과 캡처

| 검사 | 결과·범위 |
|---|---|
| 자동 검사 | 테스트 37개, 타입 검사·프로덕션 빌드 통과 |
| 공개 데이터 연결 | 서울 Supabase의 사진 검증 기록을 잠시 공개해 카드 작성자·상세·사진 표시 확인 |
| 로그인·로그아웃 | 메인 화면 GitHub 재로그인 후 `/` 반환, 프로필 닉네임 복원·OAuth 코드 URL 정리 확인 |
| 본인 기록 보관 | 실제 회원의 보관 버튼 비활성화 확인 |
| 데모 보관 | 클릭 후 채움, 새로고침과 상세 이동 후 유지 확인 |
| 검색·필터 | RLS + Supabase/Security 태그 AND + 공부 기록 필터에서 3개, 없는 검색어에서 빈 결과 확인 |
| 페이지 | 데모 첫 20개에서 더 보기 후 24개, 중복 없음 |
| 네트워크 오류 | 로컬 서버 중단 후 오류·재시도 UI 표시, 샘플 데이터 미대체 |
| 프로덕션 재시도 | 서버 복구 후 다시 시도 버튼으로 실제 빈 목록 정상 복원 |
| 반응형 | 1280/820/390 폭의 전체 페이지 캡처에서 3/2/1열 배치와 입력·버튼 줄바꿈 확인 |
| 호스팅 권한 | 비공개로 복원한 검증 기록은 익명 feed_metadata에서 빈 결과 |
| 개발 도구 | 프로덕션 `/auth/check` 404 |

실제 회원 한 계정으로 로그인·본인 보관 제한을 확인했다. 다른 회원의 보관 성공과 실패 롤백은 모의 API 테스트, 회원 간 노출·보관 격리는 PGlite의 실제 SQL 정책 테스트로 검증했다. 두 실제 계정을 번갈아 사용하는 브라우저 검증을 완료했다고 주장하지 않는다. 추가 페이지 실패 시 기존 목록을 유지하는 처리를 구현했으며 해당 실패 상황의 브라우저 주입 검사는 별도로 수행하지 않았다.

검증용 사진 프로젝트는 종료 시 다시 비공개로 적용했다. 초안 v5, 발행 v5, source_version 5이며 공개 피드에서는 숨겨진다. 서비스에 샘플 회원이나 샘플 공개 글을 실제로 생성하지 않았다.

## 오류와 해결

- 설치한 Lucide 버전에는 Github 브랜드 아이콘 export가 없어 타입 검사가 실패했다. 일반 로그인 아이콘으로 바꿨다.
- 메타데이터 Map 값의 타입이 모호해 객체 펼치기 타입 오류가 발생했다. Map의 키·값 타입을 명시해 해결했다.
- PKCE 코드 교환 전에 URL을 정리하면 로그인 코드를 잃을 수 있어 세션 초기화 완료 후 정리하도록 구성하고 실제 GitHub 재로그인으로 확인했다.
- 카드 요약에 Markdown 사진 경로가 그대로 나타나 사진·링크 표기를 요약 텍스트에서 정리했다. 본문 사진은 상세에서 표시한다.
- 반응형 캡처는 viewport override를 적용한 전체 페이지 캡처로 검사했다. 반환된 DOM 치수는 기본 창 크기를 가리켜 판정 근거로 사용하지 않았고 실제 크기별 캡처를 열어 확인했다.

다음 범위는 작성기·내 대시보드·프로필 설정 화면이다. 이 자료는 티스토리 게시용 로컬 초안이며 아직 게시하지 않았다.
