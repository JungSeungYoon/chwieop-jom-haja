# 백엔드 통합 점검과 프런트엔드 준비

기능별 백엔드를 구현한 뒤 서로 연결될 때 상태와 접근 권한이 일치하는지 확인했다. 특히 초안 수정이 공개본을 바꾸지 않는지, 사진 교체·비공개 전환이 검색·핀·보관·관련 기록에 함께 반영되는지를 검사했다.

## 파일별 역할과 흐름

| 파일 | 역할 |
|---|---|
| `tests/backend-flow.test.ts` | 마이그레이션 7개와 두 회원·방문자로 기능 간 상태 전환 검사 |
| `scripts/check-connection.mjs` | 실제 Supabase 공개 조회와 API 상태·오류·인증 거부 검사 |
| `docs/BACKEND_CHECK.md` | 결과, 검증 범위와 프런트엔드 연결 규칙 |

통합 테스트에서는 작성자가 프로젝트와 공부 기록을 발행하고 연결·핀을 설정한다. 다른 회원은 공개 기록을 보관한다. 이후 작성자가 초안을 수정하고 사진을 교체해도 공개 검색에는 기존 발행본만 나타나는지 확인한다. 비공개·휴지통·복원·재공개를 거치며 사진과 연결, 보관함의 노출도 함께 검사한다.

실연결 스크립트는 HTTP 요청을 보내 상태 코드와 JSON 오류 코드를 확인한다. 공개 목록은 배열 응답을 반환하고, 보호된 API는 토큰이 없으면 401로 거부한다. 이번 단계는 화면 구현이 아니라 백엔드 점검이므로 새 사용자 화면 캡처는 만들지 않았다. API에서 최종 화면까지의 연결은 프런트엔드 단계에 이어 작성한다.

## 확인한 결과

- 전체 자동 테스트 34개 통과, 실패와 건너뜀 0개.
- 타입 검사와 프로덕션 빌드 통과.
- 개발 서버와 프로덕션 서버에서 실제 Supabase 공개 조회 및 23개 보호 경로의 인증 거부 확인.
- 프로덕션의 개발용 `/auth/check` 화면은 404로 차단.

PGlite의 DB 통합 테스트, 모의 API 테스트, 실제 연결 검사는 확인 범위가 다르다. 이번 실연결 검사는 데이터를 변경하지 않았으며 실제 호스팅 DB의 모든 회원 변경 기능을 새로 반복한 것은 아니다. 사진의 실제 업로드와 로그인 검증은 앞 단계 자료를 함께 참고한다.

## 점검 중 수정

연결 스크립트에서 초안 수정 요청을 PATCH로 작성해 405 응답을 받았다. 실제 구현과 API 명세의 수정 메서드는 PUT이므로 스크립트를 수정했다. 이후 두 실행 환경에서 인증 없는 수정 요청이 401로 거부되는 것을 확인했다. 애플리케이션의 수정 API 자체를 변경한 것은 아니다.

다음 단계는 최종 프런트엔드다. API 응답과 최신 버전을 연결하고 작성·탐색·포트폴리오 화면, 로딩·빈 결과·실패 처리와 반응형 구성을 구현한다. 이 자료는 티스토리 게시용 로컬 초안이며 아직 게시하지 않았다.
